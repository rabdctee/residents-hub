1. The events system

In one sentenceEvents are added in Manage Events, stored in the Event Registration (Responses) Sheet through the Events script, and shown to residents on the Events page, the Register page and the Event Photos upload form.

Pages

  • manage-events.html (Hub Admin → What’s On) — add, edit, delete and reorder events. The admin list is sorted by date. Uploading a flyer after adding an event is optional. (manage-upcoming-events.html just redirects here.)
  • index.html#events-list — the resident Events page: every upcoming event with date, time, location and labels.
  • upload-event-document.html — attaches a flyer: the Event Document Upload Handler script saves it to the Drive folder “Events Management” (replacing any file of the same name) and shares it; the page then writes its link into the Events Sheet (column F) and the Home-page box.

What each event records

Events tab columns: A name, B date, C time, D location, E coordinator email(s) for reminders, F flyer link, then G–L (added August–September 2026):

  • Category — Social Club or Manor. Manor events are run by Aveo; they are listed for information only, with no Register button. Both kinds appear together.
  • Registration — Required or Not required.
  • Cost — free text such as “$15” or “Meal at own cost”. Registration and Cost are deliberately independent: an event can need registration and still be free.
  • Register by (J), payment type (K, default “On the day”) and pay by date (L).

Older rows with these columns blank are treated as Social Club, Registration Required, payment on the day.

Two event lists — on purpose

The Hub has two separate event sources, which has caused confusion before:

  • The Events script (xUcetKOK, Event Registration Sheet) — the full list. Used by the Events page, Register page, registrations, and the photo upload form.
  • The Upcoming Events box on the Home page — a separate, hand-picked short list from the Upcoming Events Manager script (z7Zi9xPa) and the Bridgeman Downs Upcoming Events Sheet (A date as text, e.g. “Tue, Jul 21”; B event; C link). Managed in the lower part of Manage Events, where it can be reordered by dragging. Kept separate by choice so the Home page can feature selected events.

In addition, a small events widget in the Home page’s side column reads the Events tab of the Web Content Manager Sheet directly (using the API key). An event added in Manage Events will not appear in either of these Home-page boxes unless it is added there too; that is expected.

2. Registrations

  • register-for-event.html — residents choose an event and give name, unit, number attending and (optionally) email. Only Social Club events marked Registration Required are offered.
  • manage-registrations.html — the organiser’s view for one event: sorted by unit, duplicate units highlighted, add/edit/delete entries, summary totals.
  • view-registrations.html — read-only list across events, split into current and past using each event’s real date.
  • Reminder emails: every day the Events script checks for events exactly seven days away and emails the event’s coordinator(s) — the address or addresses in column E of the Events tab, separated by commas. The email gives the online, paper and total numbers, with a PDF of the Summary tab attached. An event with no coordinator email gets no reminder.

Where registrations are kept

The Form Responses 1 tab of the Event Registration (Responses) Sheet: A timestamp (or the word Paper for a paper registration typed in by hand), B event, C name, D number attending, E unit, F email, G dietary needs, H paid (tick box). New online registrations re-sort the tab by event, then name. The Summary tab is rebuilt automatically and shows each event’s totals and dietary needs.

Event names must match exactlyRegistrations are linked to an event by its name. Renaming an event after people have registered separates them from it — correct the name in column B of the registrations as well.

An older Google Form for registrations still exists; the Events script keeps its event drop-down list up to date whenever events change.

3. Home-page boxes: Upcoming Events and Announcements

  • Upcoming Events box and side-column events widget — see the “two event lists” note above. Both curated by hand.
  • Latest Announcements — managed in manage-announcements.html (committee PIN). There are three slots; each announcement has “Display From” and “Display Until” dates, and the page warns when slots are full or an announcement has expired. Drag to reorder. Every morning at 8 am a script checks for announcements due to expire within three days and emails rabd.ctee@gmail.com.
  • Calendar (index.html#events) — an embedded Google Calendar (agenda view) belonging to rabd.ctee@gmail.com, filled automatically from the Village Calendar Sheet.

4. The Village Calendar

In one sentenceThe BDRV Facility Calendar — Master Schedule Sheet is the single source of truth for every regular and one-off activity; the Facility Calendar Sync script copies it into the Google Calendar residents see, and the same data feeds the printable calendar and the Bridgeman Times.

Pages

  • facility-calendar-admin.html (own PIN; for the RC Chair and SC Convenor) — add, edit and delete activities using pick-lists, with a month/day accordion view. Each add, edit or delete updates that day on the Google Calendar within seconds. Other features: “make this recurring” (weekly, fortnightly, or monthly on chosen weeks such as the 1st and 3rd Thursday), clash checking (same venue, overlapping times, with a shared list of pairs that are “fine to overlap”), times sorted properly, a full Sync button, and Generate to fill in recurring activities ahead.
  • facility-calendar-print.html — public printable calendar in the familiar paper format: week list (prints portrait) or month grid (prints landscape); click an entry for detail on screen.

Recurring activities

The regular weekly pattern lives in the Sheet’s Recurring Template tab: weekday, time, duration, activity, venue, contact, cadence (Weekly, Fortnightly or Monthly), an anchor date for fortnightly items or the weeks of the month for monthly ones (e.g. “1,3”), and an optional start date. The script keeps three months of recurring activities filled in ahead of today, never duplicating a date+time+activity that already exists, and remembers how far it has filled. One-off events are always added by hand. To change a regular activity from now on, edit its line in the template; dates already filled in are not changed, so edit or delete those individually.

A full sync (Sync button) replaces every synced calendar entry and works through roughly 450 rows in short bursts, resuming itself every minute; it can take 10–15 minutes. Only one sync runs at a time.

Rules worth knowing

  • Only two people can edit the Sheet: rabd.ctee@gmail.com and the SC Convenor (bdsc.convenor@gmail.com). Everyone else uses the admin page.
  • An activity with no duration is treated as 60 minutes for clash checking and for the Google Calendar; one with no time becomes an all-day entry (e.g. “Shopping Bus”).
  • Every row has a permanent ID in column H, so the Sheet can be sorted safely. Columns: A date, B day, C time, D duration, E activity, F venue, G contact, H RowID.
  • The sync only touches calendar entries it created itself (marked “[BDRV-Sync]” in their description). Anything typed straight into the Google Calendar is left alone — but it won’t appear on the printable calendar or in the newsletter, and may duplicate a synced entry. Always add through the admin page.
  • The Bridgeman Times’ monthly events table is built from a CSV export of this Sheet.

5. Event Photos & Videos

In one sentenceResidents upload photos and videos for a BDRV event; the Event Media script saves each file into that event’s sub-folder in the Event Photos & Videos Drive folder and logs it in the Event Media Registry; the gallery shows them grouped by event, newest first. There is no moderation queue — uploads appear straight away.
  • event-photos-submit.html — the upload form. The event list comes from the Events script. Photos are shrunk on the resident’s device to a maximum of 2048 pixels before sending, so size never matters. Videos are sent as they are and must be under 50 MB (checked on the page and again by the script).
  • The script saves each file in the event’s sub-folder (created automatically) as “Event – Name – original file name”, shares it “anyone with the link”, and adds a row to the EventMedia tab: date, event, file name, file ID, photo/video, submitted by, unit.
  • event-gallery.html — the gallery. Tap an item to open it; arrows move through the event. Edit (credit, or move to another event) and Delete require the name and unit number the item was submitted with. The unit number is never sent to the gallery; the script checks it privately. Deleted files go to Drive’s bin, recoverable for 30 days. Items uploaded before unit numbers were recorded can only be removed by the administrator, in the Sheet and Drive.
  • “New” notices — a gold banner on the Home page and a badge beside the menu link appear when there is something new since the resident’s last visit (remembered on their device).
  • Gallery is for BDRV events only. Holiday photos go to Travel Pics.
Videos from Drive play in Google’s playerVideos residents upload play through Google Drive’s own player, whose large buttons cover much of the picture on phones. Nothing on the Hub can change that player. For important videos, use a Hub-hosted video instead (next section).

6. Hub-hosted videos

Since October 2026, videos prepared by the Hub administrator are kept in the repo’s videos folder and play in the phone’s or computer’s own video player (full picture, small buttons, full screen on iPhone and Android).

  1. Export from iMovie under 50 MB (540p, Low and “Better Quality” compression work well; about 2½ minutes per file). Split longer videos into parts.
  2. Name each file in lower case with hyphens, e.g. fashion-parade-part-1.mp4, and put it in the videos folder.
  3. In event-gallery.html, find the HUB_VIDEOS list near the top and add one line per file: the event name exactly as it appears in the gallery, the file path, the credit and the date.
  4. Commit and push with GitHub Desktop (the GitHub website will not take files over 25 MB).

Hub videos have no Edit or Delete buttons; remove a line from HUB_VIDEOS (and the file) to take one down. Keep an eye on the 1 GB site limit (Chapter 2).

7. Travel Pics

A copy of the event gallery system for holiday photos, grouped by album (a name the resident types) instead of event: travel-photos-submit.html, travel-gallery.html, the Travel Media script, its own Drive folder and the Travel Media Registry Sheet. Listed in the menu under Our Community. It records each visit on the resident’s device, ready for a “new” badge, but nothing shows one yet. Its script includes a one-off repair tool, fixMissingSharing, that re-shares any file in the Travel Pics folder that has lost its “anyone with the link” setting (useful after moving files in by hand).
