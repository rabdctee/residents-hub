1. The repository

A repository (“repo”) is a folder of files that GitHub keeps together with a full history of every change. The Hub’s repo is:

github.com/rabdctee/residents-hub — branch main

  • It is public: anyone can browse the files. That is required for free GitHub Pages hosting, and it is why nothing secret may ever be stored in it.
  • Every saved change (“commit”) is recorded with a date and a short note, so any earlier version of any page can be recovered.
  • The GitHub account is rabdctee. Who can sign in to it, and its recovery details, are recorded in the Hub Secrets Register.

2. Hosting and the bdrv.au address

GitHub Pages publishes the main branch as a website automatically. A minute or two after a change is pushed to GitHub, it is live at bdrv.au. There is nothing else to “upload”.

  • The CNAME file in the repo contains bdrv.au; this tells GitHub which address to answer to.
  • The domain name itself is registered with a domain registrar, whose settings point bdrv.au at GitHub. Registrar, account holder and renewal date: to confirm and record in the Secrets Register. If the domain lapses, the Hub disappears from bdrv.au even though nothing else has changed.
  • GitHub Pages settings are under the repo’s Settings → Pages. Leave “Enforce HTTPS” switched on.
If a change doesn’t appearWait two minutes, then reload the page. On an iPhone or iPad, the browser may keep the old copy; closing the tab and opening the page again usually fixes it. The repo’s Actions tab on GitHub shows whether the latest publish succeeded.

4. Making a change with GitHub Desktop (recommended)

GitHub Desktop is a free Mac and Windows app that keeps a copy of the repo on your computer and sends your changes up to GitHub. It handles large files (up to 100 MB) that the GitHub website will not accept.

  1. Bring your copy up to date first. Open GitHub Desktop, check “Current Repository” says residents-hub, and click Fetch origin (then Pull origin if it appears). This picks up any edits made on the GitHub website, so nothing is overwritten.
  2. Open the folder. Menu Repository → Show in Finder (or Explorer on Windows).
  3. Make the change. Edit the page in a text editor (Visual Studio Code is used for the Hub), or drag in a replacement file and choose Replace.
  4. Check it before publishing. Double-click the changed page in Finder to open it in a browser. Most layout can be checked this way; parts that fetch Google data may only work once live.
  5. Commit. Back in GitHub Desktop the changed files are listed on the left. Type a short note in the Summary box (e.g. “Add Fashion Parade video”) and click Commit to main.
  6. Push. Click Push origin at the top. The site updates within a couple of minutes.
  7. Check the live page, on a phone as well as a computer if the change affects layout.

First time on a new computer: install GitHub Desktop, sign in as rabdctee, then File → Clone Repository → rabdctee/residents-hub.

5. Small edits on the GitHub website

For a quick text fix you can edit directly on github.com: open the file, click the pencil icon, make the change, then Commit changes. This is how the monthly City Hall Concerts update is done (Hub Admin has a direct “✏️ Concerts” button). Remember to Fetch origin in GitHub Desktop before your next change there.

The website’s upload limitFiles over 25 MB cannot be uploaded through the GitHub website. Use GitHub Desktop for videos and large PDFs.

6. Undoing a change

  • Before committing: in GitHub Desktop, right-click the file and choose Discard changes.
  • After pushing: in GitHub Desktop open the History tab, right-click the commit and choose Revert changes in commit, then push. This adds a new commit that reverses the old one; nothing is lost.
  • Getting an old version of one page: on github.com open the file, click History, pick the date, and view or copy that version.

7. Adding a new page

  1. Copy an existing page with a similar layout and rename it, using lower-case words joined by hyphens (e.g. garden-club.html).
  2. Keep the palette block at the top of the styles, and include <script src="sidebar.js"></script> if it is a resident page that should show the menu.
  3. Add the link to the menu in sidebar.js and in the menu copy inside index.html; for an admin page, add a card to hub-admin.html instead.
  4. If it needs a Google Sheet or script, record them in Google Services.
  5. Add the page to the Page Directory.

8. Size limits

  • One file: up to 100 MB through GitHub Desktop; 25 MB through the website. The Hub keeps videos under 50 MB.
  • Whole site: GitHub Pages sites are limited to about 1 GB. In October 2026 the repo was about 150 MB, most of it the six Dance Party videos. Review the videos folder every few months and remove or move older videos to Drive when it grows large.
