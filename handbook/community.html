Community Content

The pages residents contribute to and browse: Classifieds, memories and history, talks, news, help pages, search, surveys and the information pages.

Three ways content gets published
  • Automatic — the resident’s entry appears straight away (Event Photos, Travel Pics, Price Checker).
  • Moderated — entries wait in a Sheet with a status, and an admin page publishes or rejects them (Classifieds, Down Memory Lane, Fireside Talks volunteers, Our Story review).
  • By editing the page — content is written into the HTML file itself, either by hand or with a helper that produces the code to paste (Our Story cards, Help & How To, surveys, Life in Our Community, City Hall Concerts, Sports Hub). These need a GitHub change to update.

Classifieds

  • classifieds.html — residents post a listing (name, unit, phone, category, headline, details, optional photo shrunk before sending). Categories, each with its own colour: For Sale, Wanted, Free to Good Home, Services, Lost & Found, General Notice. Residents can edit or remove their own listing by giving the same name and unit (spacing and curly-apostrophe differences are ignored when matching).
  • classifieds-admin.html — moderation tabs: pending, published, rejected. Publish, reject, unpublish or delete (delete just sets the status to “deleted”).
  • Data: Submissions tab of the BDRV Classifieds Sheet (personal account): A timestamp, B name, C unit, D phone (kept as text so a leading 0 isn’t lost), E category, F headline, G details, H status (pending, published, rejected, deleted), I photo link. Photos go to a Classifieds photos folder in Drive. Each new listing emails rabd.ctee and the RC Chair’s personal address.
  • Matching by headline: publishing or rejecting finds the listing by its headline; residents’ edits match headline, name and unit together. Two listings with exactly the same headline could be confused.
  • classifieds-admin.html has no PIN of its own.

Price Checker

  • savings.html — a resident types a product; the Best Buys Proxy script asks Anthropic’s Claude AI to search the web for the cheapest current price at Woolworths, Coles, Aldi, Chemist Warehouse, Priceline, Big W, Amazon, eBay and iHerb, and returns a short summary and a table of prices. Each resident’s list of tracked items is kept on their own device, not in a Sheet.
  • Costs money: each search is charged to the Anthropic account whose key is stored in the script (Project Settings → Script Properties → ANTHROPIC_API_KEY). The script accepts searches from anyone who has its address. Set a monthly spending limit in the Anthropic console.
  • The script names a specific Claude model. Anthropic retires older models from time to time; if searches start failing with an API error, the model name in the script needs updating.

Down Memory Lane

  • memories.html — residents answer a set of reminiscence questions (keepsake, childhood, teenage years, music, events, advice and more); published memories are shown from the Sheet.
  • memories-admin.html — review and publish or reject.
  • Data: Residents Hub — Down Memory Lane Sheet, Memories tab; new entries start as “pending” (status in column Q). Each new memory triggers an email to rabd.ctee and the RC Chair’s personal address.

Our Story (village history)

  • our-story.html — the village history project: question accordion, community stories with search (newest first, one open at a time), and a “From the Vault” historical section with original scans.
  • our-story-submit.html — residents share memories of the village.
  • our-story-admin.html (PIN) — review submissions; Copy Story Card HTML produces the code for an approved story, which is then pasted into our-story.html and pushed. Publishing is therefore a manual GitHub step.

Fireside Talks

  • fireside-talks.html (Residents PIN) — upcoming talks and a searchable archive of past talks; recordings play from Drive.
  • fireside-talks-submit.html — residents volunteer to give a talk.
  • fireside-talks-admin.html (PIN) — add and update talks (date, time, speaker, title, description, location, recording, status) and review volunteers; paste a Drive link or ID and the page extracts the file ID. Talk times are stored as plain text so Sheets can’t turn “10:00 AM” into a date. Talks marked Cancelled are hidden from residents.

The Roundup (What’s New)

  • whats-new.html — six tabs: Health & Wellbeing, Technology, Books/Film/TV, Local Brisbane, Science & Nature, Nostalgia. Each mixes live headlines with items added by the Hub. Listed in the menu under World News, with “Major Media Outlets” (news.html).
  • Live feeds: ABC News (Lifestyle feed for Health, topic feed 2298 for Technology, Entertainment & Culture feed for Books/Film/TV), Brisbane Times (Local), NASA (Science & Nature), Wikipedia “On This Day” (Nostalgia, events 5–100 years ago). ABC, Brisbane Times and NASA go through rss2json.com because browsers cannot read news feeds directly.
  • whats-new-add.html — add or delete an item (linked only from Hub Admin); saved to the first tab of BDRV What’s New Submissions (timestamp, category, title, blurb, link, added by). Use it for CSIRO stories and Brisbane-specific nostalgia, which have no automatic feed. The page has no PIN and its script does not check one, so anyone who found the page could add or delete items.
  • If a feed address stops working (ABC changed its rules in August 2026), the page quietly shows only the added items for that tab.

Life in Our Community

community-life.html — Arts & Crafts, Recipes, Village Life, Poetry & Writing, Music & Dance, Trivia & Quizzes and Humour. Residents contribute by email (“Share yours” buttons open an email); the administrator reviews and adds items to the page by hand. The Trivia block is marked in the code to be updated each week. Tall photos are shown in full rather than cropped.

Help & How To

  • how-to.html — the largest help page: categories (getting started, apps and services, photos, home, staying safe, new technology) with Android/iPhone tabs and searchable questions. Residents can send a question.
  • admin-how-to.html — an editor: browse, add and edit questions, then Download Updated how-to.html and upload that file to GitHub. how-to-admin.html is an older version that nothing links to.

Site search

The search box on the Home page and Help pages uses an index served by the Search script (Hub Search Logger Sheet, personal account) and logs every search — term, number of results and page — in the Search Log tab. search-admin.html manages the Pages list and the keyword mappings in Search Index (keyword, page, section, display title, active), and shows the latest 200 searches and statistics — useful for spotting what residents look for but cannot find. Neither the page nor the script asks for a PIN.

Surveys

  • survey.html — the current survey (the Village Bus Replacement survey with multi-choice questions; a paper version was also used). Responses go through the RC-Notices script into the BusSurvey tab of the RC Notices Sheet (timestamp, name/unit, first and second choice, comment). A new survey with different questions needs the script’s survey section updated too.
  • survey-admin.html — results (from published result tabs, with a registry of past surveys) and a survey builder that generates the code for a new survey.html, which is then uploaded to GitHub.

Information Sessions

info-sessions.html lists sessions (upcoming ones are written into the page and sorted by date automatically). manage-info-sessions.html is meant to record planned sessions in the BDRV Info Sessions Sheet, but its script currently points at the wrong spreadsheet, so additions probably fail (see Google Services). The manage page also has no PIN. The info page’s interest-registration form is not yet connected to a script.
