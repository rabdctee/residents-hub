2. Troubleshooting

SymptomLikely causeWhat to do
A change to a page doesn’t showNot pushed yet, still publishing, or the browser kept an old copyCheck GitHub Desktop has nothing waiting to push; wait two minutes; close the tab and reopen.
A correction or deletion to a transaction hasn’t happenedThey are applied every 15 minutes, by matching date, description and amount exactlyWait 15 minutes; check the Correction Log tab for “NO MATCH FOUND” (details).
Financial Dashboard or Reports show wrong figuresRows or columns were moved on the Dashboard or Financial Reports tabUndo the layout change, or update the fixed cell addresses in the Finances script.
A resident can’t edit or delete their gallery itemName or unit doesn’t match what they entered, or the item pre-dates unit numbersRemove it in the Event Media Registry and Drive yourself.
A save seemed to work but the data “reverted”Published feed delay (up to about 5 minutes)Look in the Sheet itself. If the change is there, wait; if not, the save failed.
A page says it “could not load”The Apps Script failed, needs re-authorising, or its address changedOpen the script, run any function once to re-authorise, check Executions for errors. If a new deployment was made, update the address in every page that uses it.
A document or photo won’t open for residentsDrive file not shared publiclyIn Drive, set sharing to “Anyone with the link can view”.
An edit to the Contact List doesn’t appearThe wrong one of the two contact-list Sheets was editedEdit the copy that is published to the web.
A new event isn’t in the photo-upload or register listIt was added somewhere other than Manage Events, or it is a Manor event or not “Registration Required”Add it in Manage Events and check its Category and Registration settings.
A new event isn’t in the Home-page boxThe Home-page boxes are curated separatelySee the two event lists.
The Google Calendar is out of step with the Village CalendarSync hasn’t run, or something was added directly to the Google CalendarPress Sync on the admin page; always add activities through the admin page.
A video won’t uploadOver 50 MB (resident upload) or over 25 MB (GitHub website)Export smaller or in parts; use GitHub Desktop for Hub videos.
A Roundup tab shows no headlinesA news feed address changed or rss2json is unavailableCheck the feed address in whats-new.html; added items still show.
A page broke after an editAn editing mistakeRevert the commit in GitHub Desktop (Chapter 2), then retry the change carefully.
Stray “\n” text appears on a pageA find-and-replace in VS Code without regex modesidebar.js removes these automatically on pages that load it; otherwise fix in the file.

3. The Hub Secrets Register

Everything sensitive belongs in one private Google Doc, owned by rabd.ctee@gmail.com and shared only with the Hub administrator and one trusted deputy. It should never be published, and never copied into the repo or this handbook. It should record:

  • Each PIN, which pages it opens, and who holds it.
  • Sign-in and recovery details for the GitHub account rabdctee and the Google accounts (or where those are kept).
  • The domain registrar, account holder, renewal date and payment method for bdrv.au.
  • Any secret keys used between pages and scripts, and the Google API key’s settings.
  • SMS service account details, once Text Updates is connected.

4. Risks and recommendations

In order of importance:

#RiskRecommendation
1One person knows how it all works. The Hub was built and is maintained single-handedly.This handbook; the Secrets Register; give a deputy access to the GitHub and committee Google accounts; walk them through one routine change.
2Key parts are owned by a personal Google account: the Classifieds, RC Notices, progress-tracker-data, Upcoming Events, Hub Search Logger and Prices Sheets, and the Upcoming Events Manager and RC-Notices scripts.Transfer ownership to rabd.ctee@gmail.com. For a script attached to a Sheet, transferring the Sheet moves the script too. Afterwards, re-check each affected page works; timed triggers may need re-creating under the new owner.
3PINs and some private data are visible to a determined person. PINs are written in public page code; the Contact List and other locked pages read published Sheets that anyone with the address can open; the transaction list has no PIN.Move private data behind Apps Scripts that check the PIN themselves (the Asset Register already does this), starting with the Residents Contact List and finance pages; then un-publish those Sheets.
4Domain renewal — if bdrv.au lapses the Hub disappears from its address.Record the renewal date; turn on auto-renew; add a reminder.
5Admin pages without a PIN. Several management pages have no PIN of their own and rely on not being found: Classifieds Admin, Manage Events, Manage Registrations, View Registrations, Upload a Document, Upload Event Document, Upload Bank Statement, Search Admin, Survey Admin, Memories Admin, Help & How-To editor, The Roundup’s Add page and Manage Info Sessions. Their scripts mostly accept requests without a key. Their addresses are visible in the public repository.Add the Hub Admin PIN check to each, starting with the upload pages; longer term, have their scripts check a key as the Asset Register does.
6Price Checker costs — each search is a paid AI request, and the script accepts searches from anyone with its address.Set a monthly spending limit in the Anthropic console; consider a simple key or daily limit in the script.
7Google Sheets API key written in index.html.Restrict it in Google Cloud Console to the Sheets API and to bdrv.au.
8Website size — videos count toward GitHub’s 1 GB limit.Quarterly check of the videos folder.
9Free outside services (rss2json.com, Open-Meteo, Wikipedia) could change or stop.Accept; the pages degrade gracefully. Check The Roundup occasionally.

5. Loose ends

Found while preparing this handbook. None is urgent; each is harmless as it stands.

  • Not linked from anywhere: role-admin.html, how-to-admin.html and hub-raise-a-concern.html are older versions of current pages — candidates for removal. chair-submissions.html was never connected to its script. body-corporate.html is reached only by its address (intended).
  • Not yet connected: Text Updates (no SMS service yet); the interest-registration form on Information Sessions; Chair Submissions (script ready, page not linked).
  • Unused leftovers: the Community Price Hub Backend script and its Prices Sheet; the event functions in the Web Content Manager script.
  • Two Issues scripts — confirm which page uses which, then consider moving all issue pages to the one that numbers issues safely, keeping the email notification.
  • Finances — two web addresses for the one project (keep both deployments up to date, or merge); old one-off report functions for January–June 2026 should not be run again.
  • Information Sessions saving — the script points at the wrong spreadsheet; a one-line fix (details). Manage Info Sessions also has no PIN.
  • Old and duplicate script projects — earlier copies of the Document Upload Web App and the Event Registration Reminder Script, and the form-attached “Untitled” projects. Retire them safely (how), checking triggers first so reminder emails are never sent twice.
  • Unused files: styles.css and search-index.json; the REGISTRY_SHEET_ID setting in index.html still names the old Document Registry but nothing uses it.
  • Two contact-list Sheets — consolidate to the published one.
  • Action Register history — edits made before the 2026 row-number fix may sit on the wrong action; worth a one-off check against the minutes.
  • Menu kept in two places — sidebar.js and a copy inside index.html. Change both, or in future make index.html use sidebar.js.
