2. Troubleshooting

SymptomLikely causeWhat to do
A change to a page doesn’t showNot pushed yet, still publishing, or the browser kept an old copyCheck GitHub Desktop has nothing waiting to push; wait two minutes; close the tab and reopen.
A correction or deletion to a transaction hasn’t happenedThey are applied every 15 minutes, by matching date, description and amount exactlyWait 15 minutes; check the Correction Log tab for “NO MATCH FOUND” (details).
Financial Dashboard or Reports show wrong figuresRows or columns were moved on the Dashboard or Financial Reports tabUndo the layout change, or update the fixed cell addresses in the Finances script.
A resident can’t edit or delete their gallery itemName or unit doesn’t match what they entered, or the item pre-dates unit numbersRemove it in the Event Media Registry and Drive yourself.
A save seemed to work but the data “reverted”Published feed delay (up to about 5 minutes)Look in the Sheet itself. If the change is there, wait; if not, the save failed.
A page says it “could not load”The Apps Script failed, needs re-authorising, or its address changedOpen the script, run any function once to re-authorise, check Executions for errors. If a new deployment was made, update the address in every page that uses it.
A document or photo won’t open for residentsDrive file not shared publiclyIn Drive, set sharing to “Anyone with the link can view”.
Someone can’t sign inName typed differently from the PIN Manager (residents use first name and unit, e.g. “Joan 20”), wrong PIN, or the role for that page isn’t tickedCheck their name and roles in the PIN Manager; if they have forgotten their PIN, issue a new welcome code for them to use on My PIN.
A page asks people to sign in againA sign-in lasts two hours in that browser tabNormal; sign in again.
A tile is missing from someone’s workbenchThe matching role isn’t ticked for them, or the tile’s role list doesn’t include itTick the role in the PIN Manager, or add the role to that tile in workbench-tiles.js.
Text Updates says Mobile Message did not accept the username or password, or there is not enough creditThe API key was replaced or deleted in Mobile Message, or the account needs topping upUpdate MM_USERNAME and MM_PASSWORD in the Text Updates script’s Script Properties; or add credit in Mobile Message. Test with testOneText.
An edit to the Contact List doesn’t appearThe wrong one of the two contact-list Sheets was editedEdit the copy that is published to the web.
A new event isn’t in the photo-upload or register listIt was added somewhere other than Manage Events, or it is a Manor event or not “Registration Required”Add it in Manage Events and check its Category and Registration settings.
A new event isn’t in the Home-page boxThe Home-page boxes are curated separatelySee the two event lists.
The Google Calendar is out of step with the Village CalendarSync hasn’t run, or something was added directly to the Google CalendarPress Sync on the admin page; always add activities through the admin page.
A video won’t uploadOver 50 MB (resident upload) or over 25 MB (GitHub website)Export smaller or in parts; use GitHub Desktop for Hub videos.
A Roundup tab shows no headlinesA news feed address changed, or the news site is refusing Google’s requestsRun testFeeds in the What’s New script; fix the address in its NEWS_FEEDS list and re-publish (Deploy → Manage deployments → pencil → New version). Added items still show.
A page broke after an editAn editing mistakeRevert the commit in GitHub Desktop (Chapter 2), then retry the change carefully.
Stray “\n” text appears on a pageA find-and-replace in VS Code without regex modesidebar.js removes these automatically on pages that load it; otherwise fix in the file.

3. The Hub Secrets Register

Everything sensitive belongs in one private Google Doc, owned by bdrv.hubadmin@gmail.com and shared only with the Hub administrator and one trusted deputy. It should never be published, and never copied into the repo or this handbook. It should record:

  • Each PIN, which pages it opens, and who holds it.
  • Sign-in, recovery and 2-Step Verification backup codes for the GitHub account rabdctee and the Google accounts, starting with bdrv.hubadmin@gmail.com (or where those are kept).
  • The domain registrar, account holder, renewal date and payment method for bdrv.au.
  • Any secret keys used between pages and scripts, and the Google API key’s settings.
  • Mobile Message (the SMS service used by Text Updates) account details.
Where it isCreated October 2026: a Google Doc called “Hub Secrets Register — PRIVATE” in bdrv.hubadmin’s Google Drive, set to Restricted.

4. Risks and recommendations

In order of importance:

#RiskRecommendation
1One person knows how it all works. The Hub was built and is maintained single-handedly.This handbook; the Secrets Register; give a deputy access to the GitHub account and the bdrv.hubadmin Google account; walk them through one routine change.
2Hub parts were spread across two accounts, including a personal one. Resolved October 2026.Done: every Sheet, Form and Apps Script was moved to bdrv.hubadmin@gmail.com on 21 October 2026, re-published and re-tested. Keep rick.vanhaeften and rabd.ctee as Editors as a safety net. Later, at leisure: move the Drive folders and the Hub Google Calendar to bdrv.hubadmin.
3Some private data is still visible to a determined person. Personal PINs (October 2026) now protect about 40 pages, and the Contact List, Text Updates and External Contacts scripts check the sign-in themselves. But the old shared PINs are still written in the pages until the changeover ends on 31 December 2026, and the Residents Only documents, the transaction list and the Dashboard figures are still read from published Sheets or open script requests.End the changeover on time and remove the legacyPin lines; stop publishing the Contact List Sheet once the Residents Data script is confirmed; then move the Residents Only documents and finance figures behind scripts that check the sign-in pass, as the Contact List now does.
4Domain renewal — if bdrv.au lapses the Hub disappears from its address.Record the renewal date; turn on auto-renew; add a reminder.
5Admin pages without a PIN. Resolved October 2026: every management page now asks for a personal PIN (View Registrations and Upload Event Document were the last, on 22 October), and most send the sign-in pass to their scripts. The older scripts may keep accepting requests without a pass until the changeover date (to confirm).After 31 December, check each script refuses requests without a valid sign-in pass.
6Price Checker costs — each search is a paid AI request, and the script accepts searches from anyone with its address.Set a monthly spending limit in the Anthropic console; consider a simple key or daily limit in the script.
7Google Sheets API key written in index.html.Restrict it in Google Cloud Console to the Sheets API and to bdrv.au.
8Website size — videos count toward GitHub’s 1 GB limit.Quarterly check of the videos folder.
9Free outside services (the ABC, Brisbane Times and NASA news feeds, Open-Meteo, Wikipedia) could change or stop.Accept; the pages degrade gracefully. Check The Roundup occasionally, and run testFeeds if a tab is empty.

  • Finances — every finance page now uses one address (ywdH4fh9); the older deployment (ytxHID43) is no longer used and can be archived. Old one-off report functions for January–June 2026 should not be run again.
  • Information Sessions saving — the script points at the wrong spreadsheet; a one-line fix (details).
  • Old and duplicate script projects — earlier copies of the Document Upload Web App and the Event Registration Reminder Script, and the form-attached “Untitled” projects. Retire them safely (how), checking triggers first so reminder emails are never sent twice.
  • Unused files: styles.css and search-index.json; the REGISTRY_SHEET_ID setting in index.html still names the old Document Registry but nothing uses it.
  • Two contact-list Sheets — consolidate to the one the Residents Data script reads, then stop publishing it to the web.

  • Menu kept in two places — sidebar.js (every other page) and a copy inside index.html (the Home page). Always change both. A note at the top of each menu points to the other copy. Making index.html use sidebar.js was considered in October 2026 and decided against: the Home page’s menu switches sections within the page, its sidebar also holds the weather, Emergency button and Upcoming Events box, and sidebar.js rearranges any page it is added to, so the change would mean rebuilding the Home page.
